# Shopify CLI API Reference

> Source: shopify.dev/docs/api/shopify-cli
> Last extracted: 2026-04-04
> Version: Latest (3.x)

## Overview

Shopify CLI is a command-line interface tool that accelerates Shopify app and theme development. It handles app initialization, extension scaffolding, configuration management, testing, and deployment through a unified CLI interface.

Shopify CLI supports:
- **Shopify Apps** — Building embedded admin apps with Remix/Node.js
- **Theme Development** — Building and deploying Liquid themes
- **Hydrogen** — Building headless storefronts (Next.js/Remix)
- **Extensions** — Generating admin, checkout, and theme app extensions
- **CI/CD Pipelines** — Automated deployment workflows

## APP COMMANDS

### `shopify app init`

**Purpose**: Initialize a new Shopify app project

**Syntax**:
```bash
shopify app init [--template <template>] [--name <name>] [--path <path>]
```

**Flags**:
- `--template <template>` — Specify app template (default: `remix`)
  - `remix` — Remix + Node.js backend (default, recommended)
  - `node` — Node.js only
  - `express` — Express.js backend
- `--name <name>` — App name (prompted if not provided)
- `--path <path>` — Directory to create app (default: current directory)
- `--no-color` — Disable color output

**Example**:
```bash
shopify app init --template remix --name my-app
```

**Output**:
- Creates app directory with scaffolded project structure
- Generates `shopify.app.toml` configuration file
- Sets up environment variables (`.env` template)
- Ready to run `shopify app dev`

---

### `shopify app dev`

**Purpose**: Start development server with live reload and tunneling

**Syntax**:
```bash
shopify app dev [--client-id <id>] [--port <port>] [--tunnel-url <url>]
```

**Flags**:
- `--client-id <id>` — Shopify API app client ID (from Developer Dashboard)
  - If omitted, prompted to select app from dashboard
- `--port <port>` — Local server port (default: `3000` for Node, `8080` for themes)
- `--tunnel-url <url>` — Public URL for Shopify tunneling (generated by CLI)
- `--reset` — Reset dev environment and clear stored settings
- `--no-update` — Skip checking for CLI updates
- `--no-color` — Disable color output
- `--verbose` — Increase output verbosity

**What It Does**:
1. Starts local development server on specified port
2. Creates secure tunnel to Shopify (URL: `https://<random>.shopify-cli.io`)
3. Registers app with Shopify using client ID
4. Hot reloads on file changes
5. Watches for TypeScript/extension changes
6. Opens preview in browser automatically

**Example**:
```bash
shopify app dev --client-id 12345abc --port 3000
```

**Output**:
```
App running at: http://localhost:3000
Tunnel URL: https://xyz123.shopify-cli.io
Dev store: https://dev-store.myshopify.com/admin
```

### `shopify app deploy`

**Purpose**: Build, version, and deploy app + extensions to Shopify

**Syntax**:
```bash
shopify app deploy [--force] [--allow-updates] [--allow-deletes]
```

**Flags**:
- `--force` — Skip confirmation prompts (for CI/CD)
- `--allow-updates` — Auto-allow new extensions and configuration updates (for CI/CD)
- `--allow-deletes` — Auto-allow extension deletions (for CI/CD, use carefully)
- `--no-release` — Create version but don't release (leave in draft state)

**What It Does**:
1. Builds app code (TypeScript, bundles frontend/backend)
2. Validates configuration (`shopify.app.toml`, extensions)
3. Creates "app version" (snapshot of config + extensions)
4. Deploys each extension
5. Marks version as released (live on app)

**CI/CD Recommended Flags**:
```bash
shopify app deploy --force --allow-updates
```

**Output**:
- App version ID created
- Extension deployment confirmations
- App is immediately live after deploy

### `shopify app release`

**Purpose**: Release a previously-created app version (without rebuilding)

**Syntax**:
```bash
shopify app release [--version <id>] [--force]
```

**Flags**:
- `--version <id>` — Specific app version ID to release (if omitted, uses latest)
- `--force` — Skip confirmation prompts

**When to Use**:
- You created a version with `--no-release` and want to release it later
- You want to release an older version
- Separate build and release steps in CI/CD

### `shopify app config link`

**Purpose**: Link local app to Developer Dashboard app and pull configuration

**Syntax**:
```bash
shopify app config link [--client-id <id>] [--reset]`
```

**Flags**:
- `--client-id <id>` — Shopify API client ID to link (prompted if omitted)
- `--reset` — Clear all stored settings and start fresh
- `--no-color` — Disable color output
- `--verbose` — Increase output verbosity

**What It Does**:
1. Links local project to a Shopify app from the Developer Dashboard
2. Pulls app configuration (scopes, billing, webhooks) into `shopify.app.toml`
3. Creates `shopify.app.toml` if it doesn't exist
4. Stores client ID for future commands

**Example Workflow**:
```bash
# Create app in Dashboard first, copy client ID
shopify app config link --client-id abc123xyz

# Now shopify.app.toml is populated with your Dashboard config
# Ready to run: shopify app dev
```

**Output**:
```
Linking to app: My Awesome App (abc123xyz)
Configuration pulled and saved to shopify.app.toml
```

### `shopify app generate extension`

**Purpose**: Scaffold a new extension within your app

**Syntax**:
```bash
shopify app generate extension [--template <template>] [--name <name>]
```

**Flags**:
- `--template <template>` — Extension type to generate
  - See "Extension Types" section below for complete list
  - Examples: `admin_post_purchase_checkout`, `product_subscription`, `order_discount`, etc.
- `--name <name>` — Extension directory name (prompted if omitted)

**What It Does**:
1. Creates extension directory in `extensions/`
2. Scaffolds code files (TypeScript, config)
3. Generates `shopify.extension.toml` configuration
4. Auto-wires into main app configuration
5. Ready to develop immediately

**Example**:
```bash
shopify app generate extension --template admin_post_purchase_checkout --name my-checkout

# Creates: extensions/my-checkout/
#   ├── shopify.extension.toml
#   ├── src/
#   │   ├── index.ts
#   │   └── index.test.ts
#   └── tsconfig.json
```

## THEME COMMANDS

### `shopify theme dev`

**Purpose**: Start local theme development server with hot reload

**Syntax**:
```bash
shopify theme dev [--store <store>] [--port <port>] [--theme <id>]
```

**Flags**:
- `--store <store>` — Shopify store domain (e.g., `mystore.myshopify.com`)
- `--port <port>` — Local server port (default: `9292`)
- `--theme <id>` — Create/use specific development theme (default: auto-create)
- `--poll` — Use polling instead of file watching (for some environments)
- `--live-reload` — Enable live reload on CSS/section changes (default: true)
- `--host <host>` — Host to bind to (default: `127.0.0.1`)

**What It Does**:
1. Uploads theme as development theme to store
2. Starts local server on port 9292
3. Serves theme preview at `http://127.0.0.1:9292`
4. Hot reloads CSS and sections on file changes
5. Full page reload on Liquid changes

**Development Theme Features**:
- Don't count toward store theme limit (max 20)
- Auto-delete after 7 days of inactivity
- Preview-only (not customer-facing)

**Example**:
```bash
shopify theme dev --store mystore.myshopify.com

# Output:
# Development theme created
# Preview: http://127.0.0.1:9292?preview_theme_id=123456
```

---

### `shopify theme push`

**Purpose**: Upload local theme files to Shopify store, overwriting remote

**Syntax**:
```bash
shopify theme push [--theme <id>] [--strict] [--development]`
```

**Flags**:
- `--theme <id>` — Target theme ID to overwrite (prompted if omitted)
- `--strict` — Require `shopify theme check` to pass without errors (warnings allowed)
- `--development` — Create new development theme instead of overwriting
- `--allow-live` — Allow pushing to live theme (dangerous, requires confirmation)
- `--no-color` — Disable color output

**What It Does**:
1. Uploads all local theme files to Shopify
2. Overwrites remote theme with same ID
3. Optionally validates against theme best practices
4. Returns admin editor URL and preview link

**Danger**: Use carefully on live themes. Consider `--development` flag instead.

**Example**:
```bash
shopify theme push --theme 123456 --strict

# Output:
# Pushing theme...
# Validating (--strict)...
# Admin editor: https://mystore.myshopify.com/admin/themes/123456/editor
# Preview: https://mystore.myshopify.com/?preview_theme_id=123456
```

---

### `shopify theme pull`

**Purpose**: Download remote theme files to local directory

**Syntax**:
```bash
shopify theme pull [--theme <id>] [--store <store>]
```

**Flags**:
- `--theme <id>` — Specific theme ID to pull (prompted if omitted)
- `--store <store>` — Shopify store domain
- `--nodelete` — Don't delete local files not on remote

**What It Does**:
1. Downloads all theme files from Shopify
2. Overwrites local files with remote versions
3. Deletes local files that don't exist remotely (unless `--nodelete`)

**Example**:
```bash
shopify theme pull --theme 123456

# Downloads all theme files locally
# Ready to edit and push back
```

---

### `shopify theme check`

**Purpose**: Validate theme against Shopify best practices and Liquid standards

**Syntax**:
```bash
shopify theme check [--path <path>] [--auto-correct]
```

**Flags**:
- `--path <path>` — Theme directory to check (default: current)
- `--auto-correct` — Automatically fix correctable issues
- `--fail-level <level>` — Fail on error or warning (default: `error`)
  - `error` — Fail only on errors
  - `suggestion` — Fail on any warning or error
- `--json` — Output results as JSON

**Checks**:
- Liquid syntax validity
- Performance best practices
- Accessibility issues
- Theme structure standards

## CONFIGURATION FILES

### `shopify.app.toml` — App Configuration

Main configuration file in app root. Defines scopes, billing, webhooks, embedded settings.

**Structure**:
```toml
name = "My App"
scopes = "write_products,read_customers,write_orders"
type = "public"

[build]
  dev = "npm run dev"
  build_dir = "dist"

[webhooks]
  api_version = "2025-04"

[[webhooks.subscriptions]]
  topics = ["orders/create", "products/update"]
  uri = "https://example.com/webhooks/orders"

[pos]
  embedded = false

[[billing.plans]]
  name = "Professional"
  price = 25.00
  return_url = "https://example.com/billing"

[[billing.plans.features]]
  name = "feature_name"
```

### `shopify.extension.toml` — Extension Configuration

Per-extension config. Auto-generated by `shopify app generate extension`.

**Structure**:
```toml
name = "my-checkout-extension"
type = "checkout_ui_extension"
handle = "my-checkout-extension"

[settings]
  title = "My Checkout Extension"

[targets]
  - "purchase.checkout.shipping-option-list.render-after"
```

### `.shopifyrc` or `.env` — Environment Variables

**Required for local development**:
```
SHOPIFY_API_KEY=your_api_key
SHOPIFY_API_SECRET=your_api_secret
SHOPIFY_SHOP=your-dev-store.myshopify.com
```

## COMMON WORKFLOWS

### Initialize a New App
```bash
# Create app in Developer Dashboard first, copy Client ID
shopify app init --template remix --name my-app
cd my-app
shopify app config link --client-id abc123xyz
shopify app dev
```

### Generate and Deploy an Extension
```bash
# In app directory
shopify app generate extension --template post_purchase_checkout --name my-upsell
# Edit extension code in extensions/my-upsell/
shopify app deploy
```

### Deploy to Production
```bash
# In CI/CD pipeline
shopify app deploy --force --allow-updates
```

### Theme Development Workflow
```bash
# Start local dev server
shopify theme dev --store mystore.myshopify.com

# In another terminal, edit Liquid files
# Changes hot-reload on save

# When ready to deploy to production
shopify theme push --theme 123456 --strict --allow-live
```

### Release Separate from Deployment
```bash
# Build and create version (without releasing)
shopify app deploy --no-release

# Later, release the version
shopify app release --version xyz123
```

- `--help` — Display help for command

## CI/CD Integration

### GitHub Actions Example

```yaml
name: Deploy Shopify App

on:
  push:
    branches: [ main ]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-node@v2
        with:
          node-version: '18'

      - run: npm install -g @shopify/cli
      - run: npm install

      - run: shopify app deploy \
          --force \
          --allow-updates \
          --client-id ${{ secrets.SHOPIFY_CLI_CLIENT_ID }}
```

### Environment Variables for CI/CD
- `SHOPIFY_CLI_CLIENT_ID` — App client ID
- `SHOPIFY_CLI_API_ACCESS_TOKEN` — (if using token auth instead of interactive)

## Pitfalls

### Common Mistakes

1. **Running `shopify app config push`** — This command is deprecated; use `shopify app deploy` instead
2. **Forgetting `--allow-updates` in CI/CD** — Deploy will fail if new extensions aren't auto-approved
3. **Using `--allow-live` on theme push** — Overwrites live theme; use `--development` instead for safety
4. **Not running `shopify theme check`** — Check for errors before pushing to avoid breaking storefront
5. **Letting dev themes pile up** — Dev themes auto-delete after 7 days; clean them up manually if needed
6. **Mixing `shopify.app.toml` and Dashboard configuration** — Keep Dashboard as source of truth; pull regularly
7. **Pushing to production without testing** — Always test in dev environment first
8. **Forgetting to lock dependencies** — Use `npm ci` in CI/CD, not `npm install`
9. **Not handling sensitive config** — Never commit `.env` or API keys; use GitHub Secrets
10. **Assuming hot reload works for all files** — Hot reload works for CSS/sections; full page reload needed for Liquid logic changes
