# Shopify Metafield + Metaobject Modeling

**Owner:** lattice (Shopify Website Team)
**Cross-pod consumers:** conduit, loom, dato (mentor)
**Status:** v1.0 (foundational; expanded after first 5 client content models)

## Purpose

Design correct Shopify content schemas. Wrong choice → data migration headache. This pattern is the canonical decision tree.

## Decision Tree (Metafield vs Metaobject)

```
Need to add custom data X.

Q1: 1:1 attached to single resource?
  YES + simple value (text, number, image, boolean) → METAFIELD
  YES + references another resource → METAFIELD with reference type
  NO → continue

Q2: Reusable entity with multiple fields?
  YES → METAOBJECT
  NO → re-evaluate

Q3: 1:N relationship?
  YES → METAOBJECT (per item) + METAFIELD list.metaobject_reference on parent

Q4: Editorial / shared across resources?
  YES → METAOBJECT
```

## Namespace Strategy

NEVER use `custom` namespace. Use semantic: `{client_handle}.{domain}`.

Examples:
- `acme.product` — product enrichment
- `acme.collection` — collection enrichment
- `acme.theme` — theme-specific content (lookbooks, hero settings)
- `acme.content` — editorial (FAQs, hero copy)
- `acme.compliance` — regulatory data

## Mandatory Validation Rules

Every field gets:
- Type — most specific available
- Description — visible to merchants in admin
- Validations — max length, regex, choices
- Storefront API access toggle — ON if rendered
- Display name + key — explicit, not autogenerated

For metaobjects:
- `display_name_key` (which field shows in admin list)
- `access.storefront = "PUBLIC_READ"` if theme renders
- Capabilities (translations, publishable, online_store URLs)

## Standard Metaobject Library

For every Shopify Website Team client storefront, define these 10 metaobjects when applicable:

1. `testimonial`
2. `team_member`
3. `location`
4. `faq_entry`
5. `lookbook`
6. `feature_highlight`
7. `press_mention`
8. `recipe_step` (food brands)
9. `size_chart` (apparel)
10. `case_study` (B2B)

## Standard Product Metafields (most ecom)

- `ingredients`, `allergens` (food/beauty)
- `materials`, `care_instructions` (apparel/home)
- `country_of_origin` (all)
- `sustainability_badges` (list.metaobject_reference)
- `size_chart` (file_reference or metaobject_reference)
- `key_benefits`, `how_to_use` (beauty/skincare)

## Anti-Patterns

1. Use `custom` namespace
2. Define unbounded text fields for structured data
3. Skip validation rules
4. Define metaobject without `display_name_key`
5. Use metafields for what should be metaobjects (1:N)
6. Skip Storefront API toggle if rendered
7. Delete metafield definitions in production
8. Define metaobjects without merchant editor UX consideration
9. Bypass GraphQL schema typing in Liquid render
10. Two namespaces sharing semantic meaning
