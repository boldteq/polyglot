# Claude Hub Integration Guide — Local Agent Calls from Any Project

> Priority: HIGH — Prevents broken builds from incorrect SDK installation
> Applies to: All stacks when integrating Claude Hub agent calls
> Agents: Koda (implementation), Riko (scaffold), Yash (orchestration), Vex (debug)
> Last updated: 2026-04-05

---

## What is Claude Hub?

Claude Hub is a **local Node.js Express server** running on `localhost:3847` that manages all Boldteq agents. It provides:
- `/api/playground/run` — Execute any agent (SSE streaming response)
- `/api/global/agents` — List all available agents
- `/api/memory/*` — Read/write to the shared memory system

Claude Hub runs **only during local development** (auto-starts via LaunchAgent on macOS login). It is **never available in production** — Lovable, Vercel, CI/CD, and all deployed environments cannot reach localhost.

## The Three Integration Patterns

### Pattern 1: Lovable/Vite Browser Apps (React SPA)

**Use this for:** the project, or any Lovable-origin Vite + React project.

**Method:** Standalone helper file — NO npm package, NO `file:` dependency.

```
src/lib/claudeHub.ts    ← Helper file (auto-generated by Claude Hub, or create manually)
.env.local              ← VITE_CLAUDE_HUB_URL=http://localhost:3847
```

**Helper file (`src/lib/claudeHub.ts`):**
```typescript
const CLAUDE_HUB_URL = import.meta.env.VITE_CLAUDE_HUB_URL || 'http://localhost:3847'

export async function callAgent(agentName: string, prompt: string, timeoutMs = 120000) {
  const controller = new AbortController()
  const timeout = setTimeout(() => controller.abort(), timeoutMs)

  try {
    const response = await fetch(`${CLAUDE_HUB_URL}/api/playground/run`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ agentName, prompt }),
      signal: controller.signal,
    })
    clearTimeout(timeout)
    if (!response.ok) throw new Error(`Claude Hub returned ${response.status}`)

    const text = await response.text()
    const events = text
      .split('\n')
      .filter(line => line.startsWith('data: '))
      .map(line => { try { return JSON.parse(line.slice(6)) } catch { return null } })
      .filter(Boolean)

    const errorEvent = events.find((e: any) => e.type === 'error')
    if (errorEvent) return { success: false, output: '', agent: agentName, error: errorEvent.error }

    const doneEvent = events.find((e: any) => e.type === 'done' || e.type === 'complete')
    return { success: true, output: doneEvent?.output || '', agent: agentName }
  } catch (err) {
    clearTimeout(timeout)
    return { success: false, output: '', agent: agentName, error: 'Claude Hub not reachable' }
  }
}

export async function isOnline(): Promise<boolean> {
  try {
    const res = await fetch(`${CLAUDE_HUB_URL}/api/global/agents`, { signal: AbortSignal.timeout(3000) })
    return res.ok
  } catch { return false }
}
```

**Usage in a React component:**
```typescript
import { callAgent, isOnline } from '@/lib/claudeHub'

// Check if Claude Hub is available (dev-only feature)
const hubAvailable = await isOnline()

// Call an agent
const result = await callAgent('quill', 'Write a tagline for the project')
if (result.success) {
  console.log(result.output)
}
```

**Critical rules for Lovable/Vite:**
1. **NEVER add `@boldteq/agents` to package.json** — no `file:` or `link:` deps
2. **NEVER import from `@boldteq/agents`** — import from `@/lib/claudeHub`
3. **Use `import.meta.env.VITE_CLAUDE_HUB_URL`** — not `process.env` (Vite uses import.meta)
4. **Guard all Claude Hub calls** — check `isOnline()` first, gracefully degrade if Hub is down
5. **Add `.env.local` to `.gitignore`** — the Hub URL is local-only
6. **NEVER call Claude Hub from production code paths** — wrap in `if (import.meta.env.DEV)` guard

**Production safety pattern:**
```typescript
async function callAgentSafe(agent: string, prompt: string) {
  // Only attempt in development — Hub doesn't exist in production
  if (!import.meta.env.DEV) {
    return { success: false, output: '', agent, error: 'Claude Hub only available in dev' }
  }
  return callAgent(agent, prompt)
}
```

### Pattern 2: Node.js Server Apps (Express, etc.)

**Use this for:** Claude Hub itself, custom API servers, CLI tools.

**Method:** SDK package via `file:` dep (if SDK is inside the project) or copied SDK.

```
# If SDK is inside the project (e.g., claude-hub/sdk/)
"@boldteq/agents": "file:sdk"     ← OK for local-only Node.js servers

# If SDK is outside the project
"@boldteq/agents": "file:lib/boldteq-agents"   ← Copy SDK into project first
```

**Usage:**
```javascript
const { callAgent, listAgents, isOnline } = require('@boldteq/agents')

const result = await callAgent('sage', 'Review this code for security issues')
```

**Rules for Node.js servers:**
1. `file:` deps within the same project are OK for local-only servers
2. `file:../other-project/sdk` (cross-project) ALWAYS breaks in CI/CD — don't do it
3. If the server deploys anywhere (Vercel, Railway, Docker), copy the SDK into the project
4. Set `CLAUDE_HUB_URL` env var if Hub runs on a different port

### Pattern 3: Shopify Apps (Remix/React Router)

**Use this for:** Pinzo or any Shopify app that needs agent calls during development.

**Method:** Same as Pattern 1 (standalone helper file), but adapted for Remix/React Router.

For Remix apps, create `app/utils/claudeHub.server.ts` (server-side only):
```typescript
const CLAUDE_HUB_URL = process.env.CLAUDE_HUB_URL || 'http://localhost:3847'

export async function callAgent(agentName: string, prompt: string) {
  // Only works in development
  if (process.env.NODE_ENV !== 'development') {
    return { success: false, output: '', error: 'Claude Hub only available in dev' }
  }
  const res = await fetch(`${CLAUDE_HUB_URL}/api/playground/run`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ agentName, prompt }),
  })
  // ... same SSE parsing as above
}
```

**Rules for Shopify apps:**
1. Agent calls are **server-side only** (`.server.ts` suffix in Remix)
2. Never expose Claude Hub to the storefront or customer-facing pages
3. Use `process.env.CLAUDE_HUB_URL` (not `import.meta.env`)
4. Guard with `NODE_ENV !== 'development'` check

## Decision Tree: Which Pattern?

```
Is this a Lovable/Vite project (React SPA)?
├─ YES → Pattern 1: Helper file at src/lib/claudeHub.ts
│         - No package dependency
│         - import.meta.env.VITE_CLAUDE_HUB_URL
│         - Guard with import.meta.env.DEV
│         - NEVER add to package.json
│
├─ Is this a Shopify app (Remix/React Router)?
│   └─ YES → Pattern 3: Server-side helper at app/utils/claudeHub.server.ts
│             - process.env.CLAUDE_HUB_URL
│             - Guard with NODE_ENV check
│             - .server.ts suffix (never client-side)
│
└─ Is this a Node.js server (Express, CLI)?
    └─ YES → Pattern 2: SDK package
              - file:sdk if SDK is inside project
              - Copy SDK if it's outside project
              - process.env.CLAUDE_HUB_URL
```

## Claude Hub API Quick Reference

| Endpoint | Method | Purpose | Body |
|----------|--------|---------|------|
| `/api/playground/run` | POST | Execute an agent | `{ agentName, prompt }` → SSE stream |
| `/api/global/agents` | GET | List all agents | — |
| `/api/memory/read` | POST | Read a memory file | `{ path }` |
| `/api/memory/write` | POST | Write to memory | `{ path, content }` |
| `/api/setup/install-sdk` | POST | Install SDK helper | `{ projectPath }` → auto-detects project type |

**SSE Response Format** (from `/api/playground/run`):
```
data: {"type":"token","content":"partial output..."}
data: {"type":"token","content":"more output..."}
data: {"type":"done","output":"full agent response"}
```
Or on error:
```
data: {"type":"error","error":"Agent failed: ..."}
```

## Common Mistakes (NEVER DO THESE)

| Mistake | Why It Breaks | Do Instead |
|---------|--------------|------------|
| `"@boldteq/agents": "file:../claude-hub/sdk"` in Lovable project | `file:` deps with `../` break in Lovable, Vercel, CI/CD | Use helper file pattern (Pattern 1) |
| `import { callAgent } from '@boldteq/agents'` in Vite app | Package doesn't exist in production builds | `import { callAgent } from '@/lib/claudeHub'` |
| Calling Claude Hub in production code | localhost:3847 doesn't exist in deployed environments | Guard with `import.meta.env.DEV` |
| `process.env.CLAUDE_HUB_URL` in Vite app | Vite doesn't expose `process.env` to browser | `import.meta.env.VITE_CLAUDE_HUB_URL` |
| Running `install-sdk` without checking project type | Old endpoint added `file:` deps to everything | Updated endpoint auto-detects Vite projects |
| Calling Claude Hub from Shopify storefront | Exposes internal dev tool to customers | Server-side only (`.server.ts`) |

## New Features (2026-04-10, ruflo-inspired)

### Agent Performance Learning System

Every agent run is auto-tracked. Over time, the system learns which agent performs best for each task type.

**SDK Usage:**
```javascript
const { recordAgentLearning, getBestAgent } = require('@boldteq/agents')

// Auto-recorded on every run, but manual recording also available:
await recordAgentLearning('koda', 'build', { success: true, duration: 45000, tokens: 5000 })

// Get best agent for a task type:
const best = await getBestAgent('test')
// { recommendation: 'luna', successRate: 94, alternatives: [...] }
```

**API Endpoints:**
| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/learning` | GET | Full learning database |
| `/api/learning/route/:taskType` | GET | Best agent for task type |
| `/api/learning/agent/:name` | GET | Agent performance profile |
| `/api/learning/record` | POST | Record manual learning event |

### Claims System (Prevent Duplicate Work)

Agents claim tasks before starting. 30-minute auto-expiry. Supports handoff.

**SDK Usage:**
```javascript
const { claimTask, releaseClaim, isTaskClaimed } = require('@boldteq/agents')

// Check before starting
const check = await isTaskClaimed('build-auth-page')
if (check.claimed) return // someone else has it

// Claim it
await claimTask('build-auth-page', 'koda', 'Building auth page')

// Release when done
await releaseClaim('build-auth-page', 'completed', 'Auth page built')
```

**API Endpoints:**
| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/claims` | POST | Claim a task |
| `/api/claims/:taskId` | PUT | Release/complete claim |
| `/api/claims/:taskId/handoff` | POST | Hand off to another agent |
| `/api/claims` | GET | List all claims |
| `/api/claims/:taskId` | GET | Check if claimed |

### Cost-Based Model Routing (60-75% savings)

Routes tasks to the cheapest model that can handle them.

| Agent | Default Model | Why |
|-------|---------------|-----|
| Quill, Luna, Hawk, Mira | Haiku ($0.25/M) | Structured/pattern tasks |
| Koda, Sage, Vex, Nova, Zeph, Bolt, Vega | Sonnet ($3/M) | Reasoning + execution |
| Arya, Yash | Opus ($15/M) | Deep architecture/orchestration |

**SDK Usage:**
```javascript
const { getRecommendedModel } = require('@boldteq/agents')
const rec = await getRecommendedModel('koda', 'Build a settings page')
// { model: 'sonnet', tier: 'medium', reason: 'Agent koda defaults to sonnet' }
```

### Data Files
- `agent-learning.json` — Performance learning data (auto-generated)
- `claims.json` — Active/completed task claims (auto-generated)
- `model-routing.json` — Routing rules (auto-generated with defaults, editable)
